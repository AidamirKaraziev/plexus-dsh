# Changelog

## 0.1.2 (бандл) · витрина 0.1.6

- `@plexus-dsh/scout` 0.2.2: разведчик работает без подписки OpenCode Go. Если в DSH нет маршрута `opencode-go` или дешёвая модель не ответила до первого шага, ребёнок запускается на модели основной сессии. Раньше вызов падал с `[scout: error]` и «no adapter registered for provider "opencode-go"». Настраивать ничего не нужно; в строке `usage.jsonl` видно поле `fallback` с причиной.
- `@plexus-dsh/bundle` 0.1.2 тянет scout 0.2.2; meter, warm и read-cap остаются 0.1.1.

## 0.1.2

Выпуск витрины; версии пакетов @plexus-dsh в npm не менялись (бандл 0.1.1).

- Витрина: адаптер `plexus-workers` (источник из репозитория) заменён пакетом `@plexus-dsh/plexus` (npm, 2.11.3): 14 команд `/plexus-*` и работники `plexus-programmer`, `plexus-analyst`. Генератор индекса берёт последнюю версию из `npm view`, а при 404 пропускает плагин с предупреждением; `tools/проверка_маркета.py --индекс <файл|URL>` проверяет локальный `market.json` до выпуска витрины.
- README витрины: Install двух плагинов — бандла и `@plexus-dsh/plexus`, запасной путь из npm для обоих.

## 0.1.1

Выпуск в витрину и индекс маркета.

- Установка через Discover в DSH: индекс `market.json` в корне репозитория, два плагина — бандл `@plexus-dsh/bundle` и адаптер `plexus-workers`.
- Пакеты опубликованы в npm под scope `@plexus-dsh` (бандл, `meter`, `warm`, `read-cap` 0.1.1, `scout` 0.2.1); запасной путь — `dsh plugin add @plexus-dsh/bundle@0.1.1`.
- README витрины описывает, как включить маркет и проверить установку.

## 0.1.0

Первый выпуск. Бандл `@plexus-dsh/bundle` для DSH 0.2.2-rc.5, четыре пакета:

- `meter` — $ и % окна лимита после каждого хода;
- `warm` — тёплый кэш в паузе человека;
- `read-cap` — обрезка больших результатов `read`, `grep`, `bash`;
- `scout` — поиск и чтение на дешёвой модели в дочернем процессе.
